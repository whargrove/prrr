## Decisions taken in this plan

- **Unconfirmed writes (prrr-3ha).** A write whose send started but got no answer is *unconfirmed*: it may or may not have reached GitHub. The marker is persisted in the row's payload as `:sent-at` (a timestamp written before the request goes out, removed when any answer arrives), because the `outbox` layout is frozen. An unconfirmed row is never re-sent blindly; a refetch of its PR decides whether it landed. Cost if wrong: a payload key that is bookkeeping, not write data; moving it to a column at 1.0 is a migration.
- **Serialisation after a timeout.** When the watchdog ends a send, the Outbox's single sending slot is released, as today: a mutation with no answer after `prrr-sync-timeout` counts as ended for SPEC 4's one-at-a-time rule. Only its PR stays held, until the refetch decides. Cost if wrong: one possible overlap with another PR's mutation after a 60-second silence; GitHub's secondary limit tolerates it.
- **What a refetch can confirm.** Thread, publish, reply, publish-reply, edit, delete, resolve, viewed and discard can be confirmed or refuted from the review data. Discussion Comments and Submit cannot (they are not in the review data): those become failed writes with a message asking the user to check the PR and then retry or drop. Cost if wrong: the user decides on two kinds of write after a timeout.
- **Lost M4 ledger.** The M4 per-task deferred-minor list that `prrr-nfa` points to was in a deleted workspace. This plan covers the items written in the bead; the final review sweeps for test gaps, docstrings and formatting in the files the tasks touch.

### Task 1: Unconfirmed writes in the Outbox (bead prrr-3ha, and prrr-nfa item 3)

**Files:** `prrr-sync.el`, `prrr-state.el`, `prrr-db.el` (only if a helper is needed), `prrr-diff.el` (only for display of an unconfirmed write), `test/prrr-sync-test.el`, `test/prrr-state-test.el`, `SPEC.md` section 7, `CONTEXT.md`.

Problems to fix (bead prrr-3ha with its notes):
1. A user retry of a timed-out write before the late answer arrives sends it again, which duplicates a comment on GitHub.
2. Emacs killed mid-send re-sends the write after a restart.
3. An edit (or delete) of a comment whose creating write timed out changes that queued row in place, and the late answer then records GitHub's comment with the old body: the edit is lost.
4. A late *failure* answer is ignored.
5. (prrr-nfa item 3) After a restart, queued writes go out only once some Review Buffer's refetch succeeds.

Required behaviour:
- **Marking.** `prrr-sync--outbox-send` stores `:sent-at` (`prrr-sync--timestamp`) in the row's payload in the database before the request starts. Any answer clears it: success deletes the row as today; a failure answer stores the row without `:sent-at`, with the attempt counted and the error recorded. The watchdog leaves it in place.
- **Pure rules in `prrr-state.el`.** `prrr-state-outbox-unconfirmed-p (row)`. `prrr-state--sendable-p` is false for an unconfirmed row, so it holds its PR exactly as a failed row does, and `prrr-db-outbox-clear-errors` (retry) cannot make it sendable. A new pure function decides from fresh review data whether an unconfirmed row landed, e.g. `prrr-state-outbox-landed (row data)` returning one of: `(landed . RESULT)` where RESULT is a plist shaped like GitHub's answer for that kind (for creations the same keys `prrr-state-outbox-created` reads: `:comment-id :database-id :created-at`, plus `:thread-id` and `:review-id` when known); `missing` (it did not land; send it again); `unknown` (review data cannot tell: `discussion`, `submit`). Matching rules:
  - `thread`/`publish`: a comment by the target's `:me` whose body equals the payload body, that starts a Thread (`reply-to` nil) on the anchor's path, created no earlier than the row's `created-at` minus a fixed clock-skew allowance (a named constant, 300 s), and not already stored before the refetch under another write (pass the stored comment ids, or compare against `data` only; choose and document). The Thread id comes from the comment.
  - `reply`/`publish-reply`: such a comment in the payload's `:thread-id` Thread.
  - `edit`: landed when the comment's body equals the payload body; `missing` otherwise; a comment gone is `landed` (nothing more to do) — document.
  - `delete`: landed when the comment is gone.
  - `resolve`: landed when the Thread's resolved flag matches.
  - `viewed`: landed when the path's Viewed state matches.
  - `discard`: landed when there is no Pending Review.
  Full unit tests for each kind, including a near miss (same body, other path; too old).
- **Resolving.** A refetch whose answer is stored (the non-raced path of `prrr-sync--refetch`) then resolves every unconfirmed row of the PR that is not being sent: `landed` records it as a success (same outcome and renames as `prrr-sync--outbox-succeeded`, factored so both share it); `missing` clears `:sent-at` so the write goes out again; `unknown` clears `:sent-at` and sets `last-error` to a message telling the user GitHub did not answer, to check the PR, then retry or drop the write (name the keys through `substitute-command-keys` or the menu letters used elsewhere in failure messages). Then the PR's writes are retried as today.
- **Triggering the refetch.** The watchdog marks the PR dirty (`prrr-sync--outbox-dirty`, with the row's stored `:target`) so `prrr-sync--outbox-refetch-idle` refetches it; `prrr-sync--outbox-refetch-idle` must treat a PR whose head row is unconfirmed as idle. `prrr-sync-retry` also marks every PR (or the given PR) with an unconfirmed row dirty, so "retry" re-checks.
- **Restart (prrr-nfa 3).** The Outbox starts by itself once per session: a public, idempotent `prrr-sync-outbox-start` that marks the PRs of unconfirmed rows dirty and runs the pump from a timer. Call it where prrr first touches the database for display in a session (the Review Queue section's insert and the Review Buffer's first render are both candidates; pick the one place every entry point reaches, document the choice). Writes queued before the restart then go out without waiting for a Review Buffer refetch.
- **Edits and deletes.** `prrr-sync--outbox-creator` never returns an unconfirmed row, so an edit or delete of what it creates is queued as its own write; it names the local id and waits (`prrr-state-outbox-ready-p`) until the creation is confirmed and renamed. `prrr-sync-discard` of an unconfirmed row still drops it (the following refetch shows what GitHub has).
- **Late answers.** A late success of an unconfirmed row that is stored and not being sent is recorded as today. A late failure of such a row is recorded like any failure answer (clears `:sent-at`, counts the attempt, keeps the error) but does not touch the sending slot.
- **Display.** `prrr-state-outbox-view` and `prrr-state-outbox-describe` show an unconfirmed write as unsent (not failed), described as waiting for GitHub's answer (choose short wording; reuse an existing face).
- **Docs.** SPEC section 7 "Write path" and "Reconciliation" describe unconfirmed writes and the timeout rule (Decisions above). `CONTEXT.md` gains no new user-facing term unless the UI shows one; if the header or describe text names the state, add it.

Tests (in `test/prrr-sync-test.el`, stubbing GitHub as the existing Outbox tests do): watchdog then retry does not resend before a refetch; refetch finding the comment records it once with GitHub's ids and renames a dependent reply; refetch not finding it resends; edit during the unconfirmed window becomes a separate edit write that goes out after the creation is confirmed; restart simulation (row with `:sent-at`, fresh session state, `prrr-sync-outbox-start`) refetches before sending; late failure recorded; discussion timeout ends as failed with the check-the-PR message.
