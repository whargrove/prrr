# Ranges and Stacks Milestone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship milestone 5 of `prrr` (SPEC.md section 15, item 5): show any of the five Ranges in the Review Buffer (default, since my last review, since I last opened the PR, one commit, between two commits), keep point on the same line when switching, comment only where GitHub numbers lines as the buffer does, survive force-pushes and moving heads without redrawing under the user, record the Bookmark when a visit ends, and step up and down a Stack from the Review Buffer.

**Architecture:** A Range is a pure value, `prrr-range` (kind, start, end) in `prrr-state.el`, with the rules that matter as pure tested functions: which commits it diffs, which sides GitHub numbers as it does (the one rule behind both "which lines take comments" and "which Threads sit inline"), how a line number at one commit maps to another, which PR is next in a Stack, and what the header says when the head moved. `prrr-diff.el` draws whatever Range `prrr-diff--range` holds and keeps the head it shows until `g`, so no background redraw changes the diff. A new `prrr-range.el` holds the commands that choose a Range, the git work they need (line mapping through `git diff -U0`, fetching a missing start by sha) and `prrr-mark-seen`; `prrr-sync.el` records the Bookmark and pins commits under `refs/prrr/`; `prrr-stack.el` opens the neighbouring PR in the same window.

Every fact below was read in the installed source under `.deps/` or checked in an `emacs -Q --batch` experiment. The code of every task was run in a throwaway copy of the repository before this plan was written: after each task `make compile`, `make lint` and `make test` passed, and the end state passes all three on Emacs 30.2 (local) and on Emacs 29.4 and 31.1 (`docker.io/silex/emacs:29.4-ci` and `:31.1-ci`, `make deps` inside the container), 451 tests each. `make bench` reports the Review Buffer within budget and unchanged from milestone 4 (open 417 files 117 ms, 2,516 files 360 ms, expand 2 ms, refresh 133 ms); it exits non-zero only because the Review Queue measures 28 ms against its 25 ms fail line, which is bead `prrr-opy`, untouched here.

**magit**
- `magit-setup-buffer-internal` (magit-mode.el:667) calls `(funcall mode)` on every call, existing buffer or not, before setting the bindings. The major mode runs `kill-all-local-variables`, so every `defvar-local` of a Review Buffer (`prrr-diff--range`, `prrr-diff--head`) is back to its default each time `prrr-diff-open` or `prrr-diff-setup-buffer` shows a PR: opening is always "default Range, current head" with no code for it.
- `magit-refresh-buffer` (magit-mode.el:1097) is what every redraw runs: `g` (`magit-refresh`), the refetch's and the Outbox's scheduled refresh (`prrr-sync--refresh`), and `forge-refresh-buffer` (forge-core.el:408), which forge runs on every magit buffer after `forge-pull`. A refresh function cannot tell them apart, so the only way to keep the diff still while forge fetches a new head is for the buffer to keep the head it shows and move it only on a command of its own (`prrr-refresh`, Task 5).
- `magit-mode-bury-buffer` (`q`) calls `magit-bury-buffer-function`, by default `magit-mode-quit-window` (magit-mode.el:1019), which calls `quit-window`. `quit-window` runs `quit-window-hook` with the window's buffer current (window.el), so a buffer-local hook sees `q`.
- `magit-run-git-async` (magit-process.el:600) returns the process. Its sentinel `magit-process-sentinel` (magit-process.el:862) refreshes the buffer the command ran in unless the process has the property `inhibit-refresh`; a sentinel set afterwards with `set-process-sentinel` can call it first and then its own callback once `process-status` is `exit` or `signal`.
- `magit-display-buffer` (magit-mode.el:706) displays through `magit-display-buffer-function` and then selects the window, which makes the displayed buffer current for the rest of the command. Binding `magit-display-buffer-function` to a function returning `(display-buffer BUFFER '(display-buffer-same-window))` keeps it in the selected window.
- `magit-commit-p` (magit-git.el:1555) is `rev-parse --verify OID^{commit}`; `magit-rev-ancestor-p` (magit-git.el:1583) is `merge-base --is-ancestor`, nil for a missing commit too.

**forge**
- `forge-repository` has a `remote` slot (forge-repo.el:58), set when forge finds the repository; forge itself fetches with `(magit-git-fetch (oref repo remote) …)` (forge-commands.el:175).
- A `forge-pullreq` built in a test without forge's database has unbound slots: everything `prrr-queue-pr` reads (`state`, `draft-p`, `updated`, `head-rev`, `base-ref`, `head-ref`, `cross-repo-p`) must be given, and `prrr-queue--assignees` stubbed, as `test/prrr-queue-test.el` already does.

**git**
- `git diff A B` compares the two trees whatever their ancestry, so a Range whose start a force-push left behind needs no special diff, only the header's "history rewritten".
- `git diff -U0 A B -- PATH` gives hunks without context; the heading `@@ -12 +12 @@` means one line, `@@ -20,0 +21,2 @@` two lines added after old line 20, `@@ -30,3 +31,0 @@` three lines removed after new line 31.
- With protocol v2 (git's default), `git fetch --no-tags REMOTE SHA` fetches any commit the remote can reach; an unknown sha fails with "not our ref" and exit 128. Checked against a local clone; whether GitHub serves a commit no ref reaches any more (an old head after a force-push) is unverified, which is why the fallback exists.
- `git update-ref refs/prrr/N/OID OID` fails ("trying to write ref with nonexistent object") when OID is not in the repository, so `prrr-sync-pin` needs no separate check.

**Emacs and the tests**
- `default-directory` is buffer-local. A test that kills the current buffer, or calls `prrr-diff-open` (which selects the new buffer's window), is left in another buffer whose `default-directory` is not the fixture repository; such a test captures the repository's directory first and runs `git -C DIR`.
- A transient prefix named `prrr-range` and the struct type `prrr-range` coexist: the struct defines `prrr-range-create`, `prrr-range-p` and the accessors `prrr-range-kind`, `prrr-range-start`, `prrr-range-end`, never a function `prrr-range`. To keep the accessors unambiguous, the Range commands are named `prrr-show-…`, not `prrr-range-…`.

## Decisions taken in this plan

- **A Range is a value; `end` nil means "the head shown".** `prrr-range` holds KIND, START and END; `default` has no START (the merge base, found at each draw) and the head-ending kinds have no END. `prrr-state-range-ends` turns a Range, the merge base and the head into the two commits to diff. Cost if wrong: a Range kind that needs more (say, a Range on another PR) adds a slot.
- **One rule, "GitHub's side", decides commenting and Thread placement.** GitHub numbers the right side at the PR's head and the left side at the merge base. `prrr-state-range-github-side-p` is true for the right side of a Range that ends at the head and for the left side of the default Range only. Lines take comments exactly there (SPEC 8), and Threads sit inline exactly there; every other line Thread of a shown file goes to "Not in this diff". So in a `commit` or `between` Range every line Thread is folded into that group, even when its line is unchanged. Cost if wrong: readers of a single commit see Threads folded; mapping their lines with `prrr-state-map-line` is a later, local change in `prrr-diff--wash-file`. File Comments are allowed in any Range ending at the head and refused in `commit` and `between`, consistent with "read-only".
- **The buffer keeps its head; `g` becomes `prrr-refresh`.** SPEC 9 binds `g` to `magit-refresh`. Every redraw goes through `magit-refresh-buffer` (facts), so "nothing re-renders underneath the user" needs a head the buffer keeps (`prrr-diff--head`) and a command that moves it: `prrr-refresh`, bound to `g` in the buffer and the menu, forgets the head and runs `magit-refresh`. Every other redraw keeps the head and the header says why it should move: "head moved, press g" when forge fetched a newer head, "head moved to 1234567 on GitHub: run forge-pull, then g" when only the refetch saw it (`prrr-state-head-notice`). `g` does not fetch. SPEC 6 and 9 are corrected in Task 13. Cost if wrong: one extra `forge-pull` when GitHub is ahead of the local ref.
- **Bead prrr-836: refuse, do not recreate.** GitHub keeps one Pending Review per viewer and anchors every Thread added to it at the review's commit. Recreating the review on the new head means deleting it with its comments or re-adding each one with remapped lines; both lose or move what the user wrote, and neither is verified against GitHub. So a new Thread for the Pending Review is refused when the review is on another commit than the head the buffer shows (`prrr-state-review-commit-problem`): at confirm time in the capture buffer, where the text is kept and `C-c C-i` can publish it at once instead, and again by the Outbox when it sends, for a review found on GitHub. The review's commit is the stored Pending Review's, or the `:commit` of the first queued new Thread, which will create it. Cost if wrong: after a push, a reviewer with pending comments must submit or discard them before commenting on the new head (or publish at once). Listed as an open question for the human.
- **The Bookmark records the head shown, when a visit ends.** SPEC 8 says "on Review Buffer kill"; decision `prrr-t9q.9` says "on close". `q` buries a magit buffer rather than killing it, so the Bookmark is recorded on `kill-buffer-hook` and on `quit-window-hook` (both buffer-local), on Submit, and by `prrr-mark-seen`; never on open, and not when Emacs exits with the buffer open. It records `prrr-diff--head`, the head the user saw, not the newer one forge may have fetched. A failure to record is reported with `message`, never raised, so the buffer still goes. Cost if wrong: a user who never closes buffers relies on `m`.
- **Where commits are pinned.** `prrr-sync-pin` writes `refs/prrr/<number>/<oid>`: when a Bookmark is recorded (so on Submit too), when a Review Buffer opens for a PR whose latest review by the viewer prrr knows (one `git update-ref`, outside the measured render), and when a `since-review` or `since-opened` Range is shown. Not on every Review Queue pull: that would cost one git process per PR per pull. Pins are never removed; a follow-up bead should prune them when a PR closes.
- **since-review comes from the Review Queue's data.** The commit is `viewer-latest-review`'s in `pullreq-meta` (`prrr-state-since-review-start`), which `prrr-pull` fetches and a Submit updates at once. The per-PR refetch does not fetch it. A PR prrr never pulled refuses since-review with a message saying so. Cost if wrong: one more field in the per-PR query, and a partial update of `pullreq-meta`.
- **A missing start is fetched in the background.** `prrr-range--fetch` runs `git fetch --no-tags REMOTE SHA` with `magit-run-git-async`, REMOTE being forge's `remote` of the repository; the buffer keeps its Range until the fetch ends, then shows the new Range, or the default one with "Could not fetch 1234567, so this is the default Range". A fetch overtaken by another Range choice changes nothing (`prrr-range--fetching`).
- **Point across Ranges.** `prrr-diff-position` names point as (PATH SIDE LINE COMMIT): a removed line is the left side at the diff's start commit, any other line the right side at its end commit. The new Range looks for the line mapped to its end commit on the right side, then mapped to its start commit on the left side, then settles on the file's heading; a file the new Range does not show leaves point where magit's redraw put it. `.` is this switch to the default Range.
- **`between` may start at the merge base.** "Diff from" offers the merge base and every PR commit but the last; "Diff to" the commits after the one chosen. Choices keep the PR's order (a completion table with identity sorting).
- **Stack steps.** Down is the PR this one is stacked on (`prrr-state--parent`); up is the oldest PR stacked on this one, so a fork in a Stack goes to its oldest branch. The candidates are the open PRs prrr pulled (`prrr-queue-open-pullreqs`, made public from `prrr-queue--open-pullreqs`) plus the current one. The neighbour opens with `prrr-diff-open` in the same window, at its own default Range (facts). At either end: "Top of the Stack" / "Bottom of the Stack", as in the queue.
- **Names.** The Range commands are `prrr-show-since-review`, `prrr-show-since-opened`, `prrr-show-commit` and `prrr-show-between` (see facts); `D` opens the transient `prrr-range`, whose `d` is `prrr-goto-default-range`, the command `.` runs. The status line's argument list becomes one VIEW plist, so later fields need no signature change.
- **Test fixture.** `test/fixtures/make-repo.sh` splits the PR into two commits, "first" (every change but line 30's) and "head" (line 30), with the same final tree, so every existing test keeps its diff. `prrr-diff-test--store-fixture` puts the fixture's Pending Review on the fixture repository's head, as a review started in that buffer would be (it was on a fake oid, which the prrr-836 check now rejects).

- [ ] **Step 1: Write the failing tests**

Append to `test/prrr-state-test.el`, before `(provide 'prrr-state-test)` (`prrr-state-test--write` and `prrr-test-meta` already exist):

```elisp
;;;; Ranges

(defun prrr-state-test--range (kind &optional start end)
  "A Range of KIND from START to END."
  (prrr-range-create :kind kind :start start :end end))

(ert-deftest prrr-state-test-range-ends ()
  (should (equal '("base" . "head")
                 (prrr-state-range-ends (prrr-state-test--range 'default) "base" "head")))
  (should (equal '("seen" . "head")
                 (prrr-state-range-ends (prrr-state-test--range 'since-opened "seen")
```

```elisp
;;;; Line mapping

(defun prrr-state-parse-hunk-ranges (diff)
  "Return the line ranges of the hunks of DIFF, a unified diff of one file.
Each is (OLD-START OLD-COUNT NEW-START NEW-COUNT), in order, read from
the hunk headings \"@@ -OLD-START,OLD-COUNT +NEW-START,NEW-COUNT @@\";
a count left out is 1."
  (let ((ranges nil) (start 0))
    (while (string-match (concat "^@@ -\\([0-9]+\\)\\(?:,\\([0-9]+\\)\\)?"
                                 " \\+\\([0-9]+\\)\\(?:,\\([0-9]+\\)\\)? @@")
                         diff start)
      (push (list (string-to-number (match-string 1 diff))
                  (if (match-string 2 diff) (string-to-number (match-string 2 diff)) 1)
                  (string-to-number (match-string 3 diff))
                  (if (match-string 4 diff) (string-to-number (match-string 4 diff)) 1))
            ranges)
      (setq start (match-end 0)))
    (nreverse ranges)))

(defun prrr-state-map-line (hunks line)
  "Return the number that LINE of the old file has in the new file, or nil.
HUNKS are the line ranges of a diff without context lines (`git diff
-U0'), as `prrr-state-parse-hunk-ranges' returns them.  nil when the
diff removes or rewrites LINE.  Switching Ranges and `.' use this to
find a line again at another commit (SPEC section 8)."
  (let ((shift 0))
    (catch 'done
      (pcase-dolist (`(,old-start ,old-count ,_new-start ,new-count) hunks)
        ;; A hunk that only adds lines names the old line they follow.
        (let ((first (if (zerop old-count) (1+ old-start) old-start)))
          (cond ((< line first) (throw 'done (+ line shift)))
                ((< line (+ first old-count)) (throw 'done nil))
                (t (cl-incf shift (- new-count old-count))))))
      (+ line shift))))

;;;; Stack steps

(defun prrr-state-stack-step (pr prs default-branch direction)
  "Return the PR next to PR in its Stack in DIRECTION, or nil.
PRS are the repository's open `prrr-pr's, PR among them.  DIRECTION
`down' is the PR that PR is stacked on (see `prrr-state--parent' for
DEFAULT-BRANCH), `up' the oldest PR stacked on PR."
  (if (eq direction 'down)
      (prrr-state--parent pr prs default-branch)
    (car (sort (seq-filter (lambda (other)
                             (eq pr (prrr-state--parent other prs default-branch)))
                           prs)
               #'prrr-state--older-p))))
```

```elisp
(defun prrr-diff--wash-file (file threads comments range start end)
  "Insert FILE's diff from START to END, the commits of RANGE, at point.
FILE is a `prrr-diff-file'; THREADS its `prrr-file-threads' or nil;
COMMENTS maps Thread ids to their Review Comments.  File Comments come
first, then the hunks with their Threads, then two hidden groups: the
Threads whose line is not in this diff (`not-in-range') and the
outdated ones (`outdated').  A Thread is on a line of this diff only
when RANGE numbers its side as GitHub does
\(`prrr-state-range-github-side-p').  Runs inside a deferred section
body, where `magit-git-wash' cannot be used, so the diff is inserted,
narrowed to, stripped of its header and washed hunk by hunk.  A diff
without hunks becomes a one-line note."
  (let* ((anchors (make-hash-table :test #'equal))
         (lines (and threads (prrr-file-threads-lines threads)))
         (placed (seq-filter (lambda (thread)
                               (prrr-state-range-github-side-p
                                range (car (prrr-state-thread-anchor thread))))
                             lines)))
    (dolist (thread (and threads (prrr-file-threads-file-comments threads)))
      (prrr-thread-insert thread (gethash (prrr-thread-thread-id thread) comments)
                          :writes (plist-get prrr-diff--data :writes)))
    (dolist (thread placed)
      (let ((key (prrr-state-thread-anchor thread)))
        (puthash key (append (gethash key anchors) (list thread)) anchors)))
    (let ((beg (point)))
      (apply #'magit-git-insert "diff" "--no-ext-diff" "--no-color" "-p" "-M" start end "--"
             (delq nil (list (prrr-diff-file-orig file) (prrr-diff-file-path file))))
      (save-restriction
        (narrow-to-region beg (point))
        (goto-char beg)
        (if (re-search-forward "^@@" nil t)
            (progn
              (delete-region beg (match-beginning 0))
              (goto-char beg)
              (magit-wash-sequence (lambda () (prrr-diff--wash-hunk anchors comments))))
          (delete-region beg (point-max))
          (prrr-diff--insert-note (if (prrr-diff-file-binary-p file)
                                      "Binary file, not shown"
                                    "No changed lines")))
        (goto-char (point-max))))
    (prrr-diff--insert-group 'not-in-range "Not in this diff"
                             (seq-filter (lambda (thread)
```

```elisp
(defun prrr-diff--walk-hunk (hunk function)
  "Call FUNCTION at the start of each diff line of HUNK, in order.
FUNCTION receives the line's KIND, OLD and NEW, as `prrr-diff--line-at'
describes them, with point at the line's start.  The lines of the
hunk's Threads are skipped."
  (save-excursion
    (goto-char (oref hunk content))
    (let ((old (car (oref hunk from-range)))
          (new (car (oref hunk to-range))))
      (while (< (point) (oref hunk end))
        (when (eq (magit-section-at) hunk)
          (let ((kind (char-after)))
            (funcall function kind
                     (and (memq kind '(?- ?\s)) old)
                     (and (memq kind '(?+ ?\s)) new))
            (pcase kind
              (?\s (cl-incf old) (cl-incf new))
              (?- (cl-incf old))
              (?+ (cl-incf new)))))
        (forward-line)))))

(defun prrr-diff--line-at (pos)
  "Describe the diff line at POS as (HUNK KIND OLD NEW TEXT), or nil.
HUNK is the line's `hunk' section, KIND its first character, OLD and
NEW its numbers in the old and new file (nil on a side it is not on),
TEXT the line without KIND.  A position in a Thread counts as the diff
line the Thread follows.  nil off a hunk and on a hunk's heading."
  (save-excursion
    (goto-char pos)
    (goto-char (line-beginning-position))
    (let* ((at (magit-section-at))
           (hunk (prrr-diff--hunk-of at)))
      (when hunk
        (unless (eq at hunk)
          (goto-char (oref at start))
          (forward-line -1)
          ;; Several Threads can follow one diff line: step past them.
          (while (and (not (bobp)) (not (eq (magit-section-at) hunk)))
            (forward-line -1)))
        (when (>= (point) (oref hunk content))
          (let ((target (point)))
            (catch 'found
              (prrr-diff--walk-hunk
               hunk (lambda (kind old new)
                      (when (= (point) target)
                        (throw 'found
                               (list hunk kind old new
                                     (buffer-substring-no-properties
                                      (min (1+ (point)) (line-end-position))
                                      (line-end-position)))))))
              nil)))))))
```

```elisp
PATH is the file around point.  On a removed line, SIDE is `left' and
LINE its number at COMMIT, the commit the diff starts at; on any other
diff line SIDE is `right' and LINE its number at the commit the diff

(defun prrr-diff-goto-line (path side line)
  "Move to LINE of SIDE in the diff of PATH and return non-nil, or return nil.
SIDE `right' counts lines at the commit the diff ends at, `left' at the
one it starts at; a context line has both numbers.  The file is
expanded, and washed when needed.  Without LINE, move to the file's
heading.  Return nil, and leave point alone, when PATH is not in the
diff or LINE is not in its hunks."

                              (prrr-diff--files))))

    (if (not line)
        (progn (magit-section-goto file) t)

                         (dolist (hunk (oref file children))
                           (when (eq (oref hunk type) 'hunk)

                              hunk (lambda (_kind old new)
                                     (when (eql line (if (eq side 'left) old new))

                         nil)))
```

```elisp
(defun prrr-diff-open (pullreq)
  "Show the Review Buffer of PULLREQ and refetch its review data in the background.
The buffer renders at once from the database and refreshes when the
refetch ends.  The commit of the viewer's latest review is pinned

    (unless (magit-rev-verify ref)
      (when (y-or-n-p (format "%s is missing; run `forge-pull' now? " ref))
```

```elisp
                              repo (prrr-db-select 'pullreq-meta :forge-repo-id (oref repo id)))))
         (pullreqs (cons pullreq others))
         (prs (mapcar #'prrr-queue-pr pullreqs))
         (next (prrr-state-stack-step (car prs) prs (oref repo default-branch) direction)))
    (and next (seq-find (lambda (other) (equal (oref other their-id) (prrr-pr-id next)))
                        pullreqs))))
```
