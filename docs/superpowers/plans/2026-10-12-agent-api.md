# Agent API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an agent read a pull request's review and write to its Pending Review as the user, and let the user hand a review to an agent, through `prrr-api.el`, four hooks, JSON export and import, and `prrr-agent.el` (milestone 7).

**Architecture:** `prrr-api.el` is a buffer-free layer over what already exists: forge lookups, the database, `prrr-sync-review-data` (review data with the Outbox applied) and `prrr-sync-write` (the single Outbox enqueue point). Every read returns JSON-ready alists, so `prrr-api-export` is the same data written as JSON and an agent calling through `emacsclient -e` gets printable values. Agent-authored comments are marked by an `:agent` flag in the Outbox payload that the Outbox carries onto the stored comment and a refetch keeps; `proposed` comments are Outbox rows of a new kind the pump never sends. `prrr-agent.el` builds a Markdown payload from the API and hands it to `prrr-agent-invoke-function`, whose default submits it to agent-shell or copies it.

**Tech Stack:** Emacs Lisp (Emacs 29.4+), magit, forge public API, emacsql (via prrr-db), json.el, optional agent-shell (never required).

**Spec:** `SPEC.md` section 10 (Agent API), with section 7 (Pending Review), section 9 (keys) and section 2 (module table). Design reasoning: `bd show prrr-t9q.8`.

## Global Constraints

- `lexical-binding: t`, GPL-3.0-or-later header, `prrr-` prefix on every symbol, no personal paths or tokens anywhere in the repository.
- Only forge's public API: `oref` on its classes, `forge-get-*`, `forge-pull`, `forge-query`, `forge-rest`, `magit-add-section-hook`. Never call a `forge--` symbol.
- All GitHub calls stay in `prrr-github.el`, all SQL in `prrr-db.el`, pure logic in `prrr-state.el`. `prrr-api.el` and `prrr-agent.el` call neither ghub nor emacsql.
- Writes are optimistic through the Outbox (`prrr-sync-write`); the API never blocks on the network.
- Every user command has a mnemonic single key and the same key in a transient (SPEC section 9). `@` is `prrr-send-to-agent` (SPEC section 9 table).
- agent-shell is optional: no `require` of it, `declare-function` for what is called, `fboundp`/`featurep` checks at run time. "Keep agent code out of the package" (prrr-t9q.8): only `prrr-agent.el` names agent-shell.
- "Everything is posted under the user's account. `prrr-agent-comment-prefix` (default "") is prepended to agent-authored bodies; nothing else is added." (SPEC section 10)
- `make compile` (warnings are errors), `make lint` (package-lint + checkdoc) and `make test` must pass before every commit.
- Use CONTEXT.md terms: Pending Review, Thread, Review Comment, File Comment, Verdict, Submit, Range, Outbox, Review Buffer.

## Rulings (decided while planning; each costs rework if wrong)

1. **Reads return alists, not structs.** Keys are the JSON keys (snake_case symbols); booleans are t/nil in Lisp and become true/false in JSON. One shape serves in-process callers, `emacsclient -e` and export. *Cost if wrong:* callers wanting structs read `prrr-db` themselves.
2. **PR designator** is a `forge-pullreq`, or `(REPO . NUMBER)` with REPO a `forge-repository` or the string `"OWNER/NAME"` (host github.com). *Cost:* GitHub Enterprise users pass the repository object.
3. **Range argument** is nil (default Range), a `prrr-range`, or a list `(default)`, `(since-review)`, `(since-opened)`, `(commit OID)`, `(between FROM TO)`. A commit missing locally is refused with a message pointing at the Review Buffer, which fetches it; the API never fetches. *Cost:* agents must ask the user to open the Range once.
4. **`prrr-api-threads` Range filter** keeps the Threads on files the Range changes. *Cost:* Threads on unchanged lines of changed files are kept.
5. **New comments are validated before they are queued:** the anchor must pass `prrr-state-anchor-problem` for the default Range, and a line comment's lines must lie inside a hunk of the PR's diff on that side. GitHub would otherwise refuse them later with HTTP 422 on an Outbox row the agent never sees.
6. **The agent flag** is payload `:agent t` on `thread` and `reply` writes. `prrr-state--outbox-comment` copies it to `agent-p`; `prrr-db-replace-review-data` keeps `agent-p` on comment ids that had it. The API never uses Immediate Publish.
7. **`proposed`** is a new Outbox kind with payload `:as` (`thread` or `reply`) plus that kind's payload. The pump skips proposed rows entirely, so they never hold back the PR's other writes. Accepting deletes the row and writes its `:as` kind with the (possibly edited) body; rejecting is the existing delete path, which drops an unsent creating write. A Discard keeps proposals: they are not in the Pending Review.
8. **Hooks** are defined where they fire: `prrr-comment-created-hook`, `prrr-reply-created-hook` and `prrr-review-submitted-hook` in `prrr-sync.el` (run when GitHub confirms the write, from `prrr-sync--outbox-record-success`), `prrr-review-buffer-opened-hook` in `prrr-diff.el` (end of `prrr-diff-open`). Created hooks get the stored `prrr-comment`; the submitted hook gets a plist `(:pr-id :verdict :body :commit)` because no submitted-review struct exists; the opened hook gets the `forge-pullreq` with the Review Buffer current. A hook that signals is reported with `message` and never stops the Outbox. *Cost:* SPEC says "struct" for submit; the plist is documented instead.
9. **`prrr-api-submit` asks the user** (`yes-or-no-p`) before queuing, showing the Verdict and the counts of pending and agent comments, unless `prrr-api-confirm-submit` is nil. An agent cannot publish a review unattended by default.
10. **Export file** defaults to `prrr/review-N.json` inside the repository's git directory (`magit-gitdir`), outside the worktree. Shape: crit-review's version-1 handoff (`version base_ref base round generated_at unresolved comments`, each comment `id type file start_line end_line side quote anchor body author round resolved replies`) extended with `pr`, `head`, and per comment `thread_id comment_id database_id state local_state agent outdated`, per reply `comment_id state local_state agent`. `type` gains `"file"` for File Comments.
11. **Import** reads the same shape. An entry without `comment_id` is a new comment (`type` `"line"` or `"file"`); a reply without `comment_id` under an entry with `thread_id` is a new reply; entries of type `"review"` are skipped and counted. Every entry is validated before anything is queued: one bad entry queues nothing.
12. **`prrr-diff--merge-base` becomes public** as `prrr-diff-merge-base` (as `prrr-diff-walk-hunk` did in M6), since the API needs the same merge base the Review Buffer shows.
13. **Accept key** is `a` (`prrr-accept-comment`), in the Review Buffer and in the `prrr-menu` Agent group with `@`. `e` on a proposed comment also accepts it (SPEC section 10). Export and import are API functions without keys.
14. **Send-to-agent diff cap:** `prrr-agent-max-diff-lines` (default 2000). A longer diff is cut with a note telling the agent to call `prrr-api-diff` per file.

## Review Focus

1. **A comment on a line outside the diff** (an agent picks a line number from the whole file): refused at call time with the hunk line ranges of that file and side, never queued. Task 4 pins it.
2. **The API from `emacsclient -e` with no Review Buffer open**, in an Emacs that only ran `(require 'prrr)`, from a buffer whose `default-directory` is elsewhere: every `prrr-api-*` function is autoloaded and works from the PR designator alone. Tasks 3 and 4 pin it.
3. **The agent flag across the Outbox and a refetch:** an agent comment keeps its "agent" badge and Submit count after GitHub accepts it and after the next refetch replaces the stored review data. Task 1 pins it.
4. **A hook that signals:** the write is still recorded, the Outbox keeps pumping, and the error shows as a message. Task 2 pins it.
5. **A proposed comment queued before other writes of the same PR:** the later writes still go out, Submit sends without it, and Discard leaves it. Task 5 pins it.

```elisp
                              :merge-base (prrr-diff-merge-base pullreq head))))

     ,@body))

(defun prrr-api--range (context range)
  "Return RANGE, a Range designator, as a `prrr-range' for CONTEXT.
RANGE is nil or (default), a `prrr-range', (since-review),
\(since-opened), (commit OID) or (between FROM TO)."
  (let ((pr-id (prrr-api--pr-id context)))
    (pcase range
      ((or 'nil '(default)) (prrr-range-create :kind 'default))
      ((pred prrr-range-p) range)
```

```elisp
  "Queue the new comments and replies in FILE, a JSON review, on PR.
FILE has the shape `prrr-api-export' writes.  An entry without a
comment_id of type \"line\" or \"file\" becomes a new Thread; a reply
without a comment_id under an entry with a thread_id becomes a reply
to that Thread; entries of type \"review\" are skipped.  Every entry
is checked before anything is queued, so one bad entry queues
nothing.  All are agent comments.  Return an alist (comments . N)
\(replies . M) (skipped . K)."

         (data (prrr-api--review-data context))
         (threads (mapcar #'prrr-thread-thread-id (plist-get data :threads)))
         (entries (alist-get 'comments

                                                  :null-object nil :false-object nil))))
         (actions nil)

                                                  :side (alist-get 'side entry)

         (t (cl-incf skipped)))))
    (when (seq-find (lambda (action) (eq (car action) 'thread)) actions)
      (prrr-api--check-commit context data))
    (dolist (action (nreverse actions))
      (prrr-api--write context (car action)
                       (append (cdr action) (list :commit (prrr-api--context-head context)))))
    `((comments . ,(seq-count (lambda (a) (eq (car a) 'thread)) actions))
      (replies . ,(seq-count (lambda (a) (eq (car a) 'reply)) actions))
      (skipped . ,skipped))))
```

```elisp
(defun prrr-agent--shell (directory)
  "Return the agent-shell buffer to use for DIRECTORY, or nil.
Prefer shells whose directory is inside DIRECTORY; prompt when
several remain."
  (when (featurep 'agent-shell)
    (let* ((root (file-truename (file-name-as-directory directory)))
           (shells (seq-filter (lambda (buffer)
                                 (with-current-buffer buffer (derived-mode-p 'agent-shell-mode)))
                               (buffer-list)))
           (here (seq-filter (lambda (buffer)
                               (string-prefix-p root (file-truename
                                                      (buffer-local-value 'default-directory buffer))))
                             shells)))
      (pcase (or here shells)
        ('nil nil)
        (`(,only) only)
        (several (get-buffer (completing-read "Agent shell: " (mapcar #'buffer-name several) nil t)))))))

(defun prrr-agent-invoke-default (markdown context)
  "Give MARKDOWN to the repository's agent-shell, or copy it.
CONTEXT is the plist of `prrr-agent-invoke-function'.  A busy shell
queues MARKDOWN as its next prompt; an idle one gets it submitted.
Without agent-shell, MARKDOWN goes to the kill ring."
  (if-let* ((shell (prrr-agent--shell (or (plist-get context :directory) default-directory))))
      (progn
        (if (with-current-buffer shell (shell-maker-busy))
            (with-current-buffer shell (agent-shell-prompt-queue markdown))
          (agent-shell-insert :text markdown :submit t :shell-buffer shell))
        (display-buffer shell)
        (message "Sent the review to %s" (buffer-name shell)))
    (kill-new markdown)
    (message "No agent-shell: the review is in the kill ring")))

(defun prrr-send-to-agent ()
  "Send this pull request's review to an agent with your instructions.
Collects the summary, the shown Range and its diff, the Threads and

        (range prrr-diff--range)

     "Instructions for the agent"

       (funcall prrr-agent-invoke-function
                (prrr-agent-markdown pullreq range text)
                (list :pullreq pullreq :directory directory :range range)))
     :allow-empty t :immediate-allowed nil)))
```
